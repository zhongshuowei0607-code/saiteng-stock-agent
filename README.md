# 赛腾股份 · 个人 A 股每日分析 Agent

程序计算事实，LLM 解释事实。本系统仅用于个人研究，不构成投资建议。不连接券商、不下单、不自动修改持仓。

## 项目架构

- `app/config`：环境变量、模型、股票池、观察区间
- `app/data`：统一行情接口，Tushare 优先、AKShare 回退；新闻、公告、基本面和同行
- `app/database`：SQLAlchemy + SQLite，行情与报告按股票/日期幂等写入
- `app/indicators`：Python 技术指标、趋势、支撑压力、企稳评分
- `app/portfolio`：只读持仓与观察状态机
- `app/analysis`：事实汇总、风险、事件、日报
- `app/llm`：OpenAI / DeepSeek / Ollama 统一接口
- `app/api`、`app/web`：FastAPI、Jinja2、ECharts
- `app/backtest`：前复权、下一交易日成交的策略回测
- `app/scheduler`：上海时区交易日 15:05 日报、盘中三次快照
- `tests`：分阶段自动测试；`data`、`reports`、`logs`：本地输出

本项目按单机本地运行设计，不包含 Docker、NAS 或远程部署配置。

## V2 设计方向

2026-11-04 的整体设计更新见 [DESIGN_V2.md](DESIGN_V2.md)。方向是从“单票 + 手工区间 + LLM 解释”升级为“因子 → 状态 → 事件否决 → 风险预算 → 执行 → 回测/纸面 → 监控”的系统化流程，参考公开量化实践中的多因子、风险优先和低换手原则。当前线上仍是 v1 规则，V2 只作为研究和纸面并存，不会自动替换现有计划。

Phase 1 已落地单票因子快照：反转、动量、波动率、相对强弱、质量、成长、估值、流动性和事件九项，输出 0–100 综合分、覆盖率、置信度、事件否决和逐项理由；Dashboard 与日报均有“因子快照（研究）”区块。它是时间序列因子，不是横截面选股，不会直接改变 v1 买卖计划。

当前参考池：A 股同行包括博众精工、立讯精密（立讯科技）、工业富联（富士康）、科瑞技术、智立方、联得装备、荣旗科技、天准科技；苹果作为全球客户/需求端，思榕智能装备和杰士德作为非上市设备商，只做定性参考，不抓取行情或财报。

## 安装（macOS，Python 3.11+）

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run.py init-db
python run.py download 603283.SH

```

在 `.env` 填入 TUSHARE_TOKEN；token 不足权限会回退 AKShare，估值缺失保留 null。不得提交 `.env`。

## 数据口径

原始不复权日 K 用于当前价、持仓估值和成交额；技术指标、支撑压力、企稳和突破判断使用前复权日 K（`adjusted_bars` 表），避免除权除息造成假的均线/RSI 缺口。前复权不可用时自动回退不复权，并在日报和页面标注。成交量单位为手，金额与市值统一为元，涨跌幅/换手率单位为百分数。请求约 800 个自然日，确保成熟股票通常超过 250 根 K；不足会标记。

官方接口参考：[Tushare](https://tushare.pro/document/2)、[AKShare 股票接口](https://akshare.akfamily.xyz/data/stock/stock.html)。数据源可能有积分、网络或频率限制，失败不会伪造数据。

## 启动与分析

```bash
python run.py                    # Web： http://127.0.0.1:8000
python run.py analyze 603283.SH   # 完整实时抓取、解释和报告
python run.py daily               # 确认当天是交易日才运行
python run.py analyze --offline   # 缓存研究，不访问网络或 LLM
python run.py backtest 603283.SH  # 用前复权数据回测当前条件计划
python run.py backtest 603283.SH --initial-shares 1100  # 从满仓开始回测
python run.py backtest 603283.SH --walk-forward  # 滚动训练窗口校准观察区
python run.py download 603283.SH --days 1500  # 拉取更长历史后再回测
python -m pytest -q               # 全部自动测试
```

`download` 下载原始行情和前复权行情，不生成报告；已有报告打开页面即可查看，点击“更新并生成日报”运行完整流程。首次启动没有报告时创建缺失/缓存报告，需点击更新才抓取网络数据。Web 服务默认仅绑定 `127.0.0.1`，只在本机访问。

## macOS 一键运行

在 Finder 中双击项目目录下的 `start.command`。脚本会自动进入项目目录、使用 `.venv`，并在服务就绪后打开默认浏览器。已有本工具服务时直接打开页面，不重复启动。

首次运行需要 Python 3.11+；缺少或失效的虚拟环境会自动重建，旧环境保留为 `.venv.backup-*`；缺少依赖时自动安装（需要联网），没有 `.env` 时从示例创建。API Key 和模型仍需按下文配置。请保留启动的终端窗口，按 `Control+C` 停止服务。

若 macOS 阻止首次打开，可右键 `start.command` → 打开。复制项目后若执行权限丢失，在项目目录运行 `chmod +x start.command`。端口 8000 被其他程序占用时会提示错误，不会关闭其他程序。

## 模型配置

当前模型配置见 `config/config.yaml`，可用 `.env` 的 `LLM_PROVIDER` / `LLM_MODEL` 覆盖。使用本机 Ollama 时，先运行 `ollama pull qwen3` 并确保 Ollama 服务已启动，再在 `.env` 设置 `OLLAMA_URL=http://localhost:11434`。

OpenAI 示例（密钥只填 `.env`）：

```dotenv
LLM_PROVIDER=openai
LLM_MODEL=填写账户实际可用的模型名称
OPENAI_API_KEY=你的密钥
```

DeepSeek 使用 `LLM_PROVIDER=deepseek`、`LLM_MODEL=deepseek-chat`、`DEEPSEEK_API_KEY=...`。`LLM_PROVIDER=disabled` 关闭模型解释。环境变量覆盖 YAML 中模型设置。切换云模型会将报告事实与持仓数据发送到选择的模型供应商。Chat Completions 接口采用 JSON 模式，再由 Pydantic 验证：[OpenAI 官方接口](https://developers.openai.com/api/reference/cli/resources/chat)。没有可用模型时仍生成报告，并显式标注 AI 未生成。

模型没有搜索或交易工具。提示词禁止外部知识补齐事实；输出校验 JSON 结构、事件 ID、即时交易措辞和未提供数值。校验是保守防线，不能证明所有自然语言解释都正确，须结合页面来源核对。

## 持仓与观察区配置

在“系统设置 → 持仓与规则”中可按成交价和股数增删买入记录，也可维护可选卖出记录与最大计划持仓。最大计划持仓是可配置的 `max_shares`，不再是固定 1000 股；当前为 1100 股。保存后系统立即重算持仓数量、平均成本、盈亏、剩余计划股数和风险评分；勾选“保存后重新分析并更新日报”时会使用新持仓重新生成 AI 日报。`data/portfolio.json` 是保存结果，所有运行入口只读取它。分红、送转、费用或人工交易后的持仓变化需要用户手工维护。成本未含手续费和现金分红，计划仓位是股数 / 最大计划持仓，并非账户总资产仓位。

`app/config/position_strategy.yaml` 配置价格区间，左闭右开；2026-10-20 已按最新收盘 34.89、强支撑 32.48、压力 36.44 / 38.00 和 MA20 40.96 校准。当前区间：32.5 以下高风险，32.5–34.4 第二加仓观察，34.4–36.4 第一加仓观察，36.4–38 持仓观察，38–41 反弹观察，41 以上反弹减仓观察。阈值只决定观察信号，不生成买卖指令，可按自己的风险偏好修改。

操作计划按固定顺序判断：数据有效性 → 严重风险（评分 ≥85）→ 持仓超限 → 高风险区 → 跌破强支撑 → 反弹减仓 → 风险警戒（65–84，只暂停加仓）→ 满足企稳 / 风险 / 额度后的加仓。风险警戒不会因为价格低就强制卖出；只有硬止损、严重风险、跌破支撑或反弹到减仓区才给出减仓参考。买入按 100 股整数倍；卖出同样按 100 股整数倍，零股只能一次性卖出；严重风险退出允许一次性卖出全部持仓（含零股）。规则依据：[上证函〔2014〕301号](https://www.sse.com.cn/lawandrules/guide/stock/jyglywznylc/tz/c/c_20230209_5716007.shtml)。

突破确认要求连续两日站上此前 20 日高点且当日相对五日均量放量；突破状态会保存到日报，但盘中报价不能重新确认突破。只有标题的事件不得触发 LLM 投资逻辑判断；可用事件解释要求暂停补仓观察时，会进入“事件风险”状态，只暂停加仓，不自动卖出。

## 自动任务

Web 服务运行期间，APScheduler 每天上海时间 15:05 检查交易日历并执行。Tushare 日历优先，AKShare 日历回退；缓存覆盖之外且获取失败时跳过。电脑关机或程序退出就不会运行，不会自动补跑关机期间的任务。应只运行一个 Web worker；操作系统文件锁同时防止 Web、CLI 和调度并发写报告。

交易日另有三次 Bark 盘中快照（可在 `scheduler.intraday` 修改）：09:35 上午开盘、11:35 上午收盘、13:05 下午开盘。快照包含现价/涨跌幅、日线短期与中期趋势、MA5/MA20/RSI、风险/企稳/观察状态、持仓浮盈亏、支撑压力和收盘计划标题；同一市场日同一场次只发一次。行情日期不是当天时跳过，不发旧数据。

日报会同时发送 Bark 摘要和邮件附件。Bark 摘要包含收盘价/涨跌幅、持仓与浮盈亏、风险/企稳、支撑压力、结论和 AI 摘要；同一市场日期只推送一次，手动重复分析或 15:05 调度重复运行不会重复发送。邮件仍保留完整 HTML 报告附件。Bark 在 `.env` 中通过 `BARK_ENABLED=true` 和 `BARK_DEVICE_KEY` 配置，可用 `python run.py test-bark` 测试。

日报时间由 `config/config.yaml` 的 `scheduler.hour` / `scheduler.minute` 控制，默认 15:05（收盘后 5 分钟）；调度会先用交易日历确认当天是交易日。15:05 若行情源尚未写入当日 K 线，这次不会发送误导性的日报推送，15:20 会自动重试一次（`scheduler.retry_hour/retry_minute`）；仍拿不到当日行情时，报告会明确标注并使用上一交易日。手动 `analyze` 不受交易日限制。

手机日报链接：默认 `WEB_HOST=127.0.0.1`、`REPORT_PUBLIC_URL` 为空，因此 Bark 只发摘要。要让手机点开完整 HTML 日报，需要填写手机能访问的地址，例如 `REPORT_PUBLIC_URL=http://192.168.0.103:8000`；局域网访问还需把 `WEB_HOST` 改为 `0.0.0.0`、把该 IP 加入 `ALLOWED_HOSTS`，并建议开启 Dashboard 密码。公网地址可用反向代理或隧道，不要把无认证的服务直接暴露到互联网。

## 回测

```bash
python run.py backtest 603283.SH
python run.py backtest 603283.SH --start 2025-01-01 --end 2026-10-20
python run.py backtest 603283.SH --initial-shares 1100
```

回测使用 `adjusted_bars` 前复权序列和当前观察区/风险阈值，信号在收盘后生成、下一交易日开盘成交，包含 100 股整数倍、涨跌停、T+1、手续费 0.03%（最低 5 元）、卖出印花税 0.05% 和滑点。输出 `reports/backtest/*.json` 与 `.md`，包含累计收益、年化、最大回撤、夏普、胜率、换手率、平均仓位和买入持有基准。

回测只覆盖价格/技术/当前配置，不重建历史新闻、公告、财务和估值；观察区是 2026-10-20 校准的，存在配置前视偏差；策略平均仓位较低时不能与满仓基准直接类比。正式调参应使用 walk-forward，不能把一次回测结果当作未来收益保证。

可选过滤器：`add_confirmation_days`（连续站上区间下沿）、`block_add_trends`（例如 `[STRONG_BEAR]`）和 `--cooldown`。当前样本中它们都会降低收益或降低仓位，默认关闭；是否启用应由 walk-forward 决定。

### Walk-forward

`--walk-forward` 每 60 个交易日用之前最多 250 个交易日的数据重新校准观察区，校准只使用支撑/压力/ATR，再从下一天开始交易。输出文件名带 `_wf`。

当前 2023-10-13 至 2026-10-20 样本：空仓起点 +38.58%、最大回撤 -9.72%、夏普 1.04；满仓起点 +36.01%、最大回撤 -9.92%、夏普 0.96；基准同期 +37.28% / +41.26%，最大回撤约 -57%。校准间隔 40/60/90 个交易日的结果分别为 +27.89% / +38.58% / +29.61%，说明结果对再校准频率敏感。

注意：walk-forward 平均仓位只有约 7%–9%，不能和满仓基准直接比较；样本只有一只股票、约 3 年、13 次再校准，且未重建历史新闻/公告/财务。它是研究工具，不会自动替换线上固定观察区。

### 纸面跟踪

每次分析还会维护一个独立的滚动校准纸面账户：

- 状态文件：`data/walkforward_shadow.json`
- 首次从当前实际持仓开始；每 60 个交易日后用最近 250 根 K 线重新校准建议区间。
- 纸面成交按当日收盘价、手续费/印花税和 100 股整数倍处理，结果明确标注为“纸面”。
- Dashboard 新增“滚动校准建议区间（研究）”面板，展示建议区间、当前所处区间、纸面权益和最近动作；也可通过 `/api/walkforward` 读取。
- 这套区间**不写入** `config/position_strategy.yaml`，不覆盖上方实际操作计划；需要人工观察一段时间后再决定是否采用。

## 报告与数据

- `data/stock_agent.db`：原始日线、前复权日线（`adjusted_bars`）、公告/新闻、财务和日报 JSON，按键幂等更新。
- `data/walkforward_shadow.json`：滚动校准建议区间和纸面账户；仅研究用途，不覆盖固定观察区。
- `reports/603283/YYYY-MM-DD.md` 与 `.html`：按生成日保存，报告单独显示行情日期。当天重复运行更新同一份报告。
- `logs/stock_agent_YYYYMMDD.log`：行情源失败、请求、LLM 状态和任务耗时。不记录密钥或完整模型请求。
- Tushare 日线估值/财务需要对应权限；AKShare 日线不提供历史 PE/PB/市值时保持缺失。
- 公告取最近 45 日、最多 15 条。东方财富接口会提取最新 3 条的正文（最多 5 万字符）；失败时回退巨潮资讯并尝试官方 PDF 前 80 页。原文/截断状态可见，模型输入每条原文最多 12000 字符，数据库保留提取到的全文。
- 公告优先使用东方财富个股公告接口，失败时回退巨潮资讯；估值按行情日期从东方财富估值数据中心补齐 PE(TTM)、PB 和市值，无法对齐日期时保持缺失。
- 公告标题或已提取正文命中“控制权变更 / 质押 / 减持 / 诉讼 / 监管 / 退市”等关键词会标记风险；控制权变更会直接阻止新增买入，并要求人工核对公告原文。
- 新闻为实际抓取的个股新闻加一只同行新闻样本，非完整行业新闻覆盖。提供来源、时间、URL 和去重 ID。
- 当分析首次进入加仓观察区、突破确认区、减仓观察区、跌破支撑、高风险区或严重风险状态时，系统会立即发送独立买入/卖出观察邮件；同一市场交易日同类信号只发送一次，避免实时轮询重复轰炸。风险警戒（65–84）只暂停加仓，不会单独触发卖出邮件。
- 邮件按当前持仓和最大计划持仓计算参考股数：第一加仓采用剩余额度的 50%，第二加仓采用全部剩余额度，突破确认采用剩余额度的 50%；反弹观察卖出当前持仓的 20%，反弹减仓、跌破支撑或高风险区卖出 50%，风险评分 ≥85 全部退出。买入按 100 股向下取整；卖出按 100 股整数倍，零股一次性卖出，严重风险退出可一次性卖出全部持仓。
- 财务保存最近 12 期，优先使用截至运行日已公告的数据；增长比较同年内对应报告期，不用单季度与全年混比。这不是带历史财务修订快照的回测系统。
- 同行须与赛腾最新行情日期对齐；缺失或停牌导致日期不一致会排除；样本不足时不给行业结论。
- 风险 0–100 为启发式权重归一化，展示可用因子覆盖率和缺失项。资金流采用 Tushare moneyflow，须有权限且日期对齐，15:05 时通常尚未发布，不会用成交量伪装资金净流入；估值阈值未作行业历史分位校准。公告/新闻风险标记是标题加已提取正文的关键词初筛，不等于完整风险判断。

## 常见错误

- Tushare ValueError：没有 Token，检查 `.env`；权限错误按源提示检查积分与接口权限，系统继续回退。
- ProxyError / TimeoutExpired：检查网络与代理；外部接口在子进程中有硬超时，可以继续用缓存。缓存不会标记为今天收盘数据。
- 只有 400 股/49 元，价格为 `—`：尚未取得行情，点击更新或运行 `download` 后 `analyze`。
- AI 未生成：检查模型名、API Key、Ollama 是否启动；系统会自动重试一次，JSON 或安全校验连续失败时仍会拒绝采用模型输出，但程序指标和已抓取事实不受影响。
- 自动任务未运行：确认进程在 15:05 存活、日历覆盖当前年份、机器时钟和网络正常。
- 端口占用：关闭已有实例，避免双开。不要开多个 Uvicorn worker。
